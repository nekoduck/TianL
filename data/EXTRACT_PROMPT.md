# 《天龙八部》硬知识抽取提示词

> 用法：把下方「提示词正文」整段发给持有原著全文的 AI。按「工作流程」分步执行，每一步产出一个 JSON 文件，
> 全部放回本目录 `data/`。我会用导入校验器把它们变成游戏世界的基础设施。

---

## 提示词正文

你是一名严谨的文学数据工程师。你手上有金庸《天龙八部》全文。请从原著中抽取构建一个文字沙盒游戏世界所需的**全部硬知识**，输出为严格的 JSON。

### 一、总原则（必须遵守）

1. **只取原著事实，不得杜撰。** 原著未明说而需要推断的字段（如某人在故事开端身在何处、两地路程天数），给出最合理的推断，并在该条目加 `"inferred": true`。
2. **版本唯一。** 先在 `meta.json` 中声明你所依据的版本（如"三联修订版（第二版）"或"世纪新修版"），全程只依据这一版。各版结局与身世设定不同，切勿混用。
3. **统一 ID。** 每个人物、地点、门派、器物、武学都有唯一的 `id`：取原著最常用的中文称呼（如「乔峰」而非「萧峰」，后改名的写进 `aliases`）。所有引用必须使用 `00_index.json` 中已登记的 id，不得自造新写法。
4. **时间切片。** 所有"初始状态"都以**故事开端**为准：第一回段誉在无量山剑湖宫观看东西宗比剑之时。此后发生的任何变化（死亡、迁移、改换门庭、得到器物、习得武学、关系变化），一律不写进初始状态，而是写进 `08_canon.json` 的事件 `effects` 里。
5. **公开与隐情分离。** 江湖中不为人知或主角不可能知道的真相（身世、真实身份、暗中师承、幕后主使等）标记为隐情（`secret: true` / `hidden: true`），并注明在哪个原著事件中被揭开。
6. **简洁。** 描述类字段严格遵守字数上限；宁可精炼，不要铺陈。
7. **出处。** 每个条目带 `"src": "第N回"`（首次出现或主要依据的回目），便于核对。

### 二、度量衡（统一尺度）

**功力 power（0~100，故事开端时的水平）**，按以下锚点校准：

| 档位 | 区间 | 锚点 |
|---|---|---|
| 不会武功 | 0~14 | 段誉(开端)=5，王语嫣=5 |
| 三流 | 15~34 | 钟灵=15，阿朱=15 |
| 二流 | 35~59 | 左子穆=40，钟万仇=45，游骥=50 |
| 一流 | 60~84 | 段正淳=60，南海鳄神=70，慕容复=80 |
| 绝顶 | 85~100 | 玄慈=85，鸠摩智=90，段延庆=92，乔峰=95，萧远山=95，天山童姥=95，无崖子=99，扫地老僧=100 |

**路程 days（整数，单程日数）**：按北宋常规行程估算，步行约日行六十里，骑马约日行百里，取江湖人常用方式；同一处的相邻子区域（如寺院内外、山上山下可当日往返）记 0。

**时间**：游戏历法以「元祐七年正月初一」为第 0 日，每月 30 日、每年 12 个月。事件日期请给出原著推断的年月（如 `"元祐八年三月"`，可附旬），并给出全书唯一的先后序号 `order`。

### 三、抽取范围与格式

#### `meta.json`
```json
{"edition": "所依据版本", "story_start": "故事开端的推断日期，如元祐七年三月", "notes": ["抽取中的重要取舍说明"]}
```

#### `00_index.json` —— ID 索引（第一步，后续一切以此为准）
```json
{
  "persons":   [{"id": "乔峰", "aliases": ["萧峰", "乔帮主", "萧大王"]}],
  "locations": [{"id": "少林寺", "aliases": ["少室山"]}],
  "factions":  [{"id": "丐帮", "aliases": []}],
  "items":     [{"id": "打狗棒", "aliases": []}],
  "skills":    [{"id": "降龙十八掌", "aliases": ["降龙廿八掌"]}]
}
```
范围：凡原著中**有名有姓、有台词或有具体行动**的人物；凡**发生过场景**的地点（含子区域）；凡出现过的门派、帮会、势力、国家朝廷；凡**被人使用、争夺、交付或描写过**的器物；凡**有名目**的武功、内功、轻功、阵法、毒术、医术。

#### `01_locations.json` —— 地点
```json
[{
  "id": "无量后山",
  "parent": "无量山",
  "region": "大理·无量山",
  "desc": "不超过60字的景观描写，依原著",
  "lore": ["不超过50字的硬设定，每处至多5条：此地的规矩、来历、机关、禁忌"],
  "state": "故事开端时的现状，可为 null",
  "src": "第1回"
}]
```
粒度要求：重要场景须细到子区域。例如「少林寺」之下应有「少林寺·藏经阁」「少林寺·菩提院」等原著出现过场景的处所，其 `parent` 为「少林寺」。`parent` 本身也必须是一个已登记的地点。

#### `02_roads.json` —— 道路
```json
[["剑湖宫", "无量后山", 0], ["无量后山", "琅嬛福地", 1]]
```
每条为 `[地点id, 地点id, 天数]`，无向。要求：**全图连通**；子区域与其 `parent` 之间必须有路；主要城镇之间按原著人物实际走过的路线连接，不必两两相连。推断的路程不必标注。

#### `03_factions.json` —— 门派与势力
```json
[{"id": "丐帮", "desc": "不超过60字", "base": "地点id或null", "leader": "故事开端时的首领人物id或null", "src": "第14回"}]
```

#### `04_persons.json` —— 人物（故事开端时的状态）
```json
[{
  "id": "段誉",
  "gender": "男",
  "age": 19,
  "title": "开端时的身份称号",
  "faction": "门派id或null",
  "status": "alive|wounded|dead",
  "location": "开端时所在地点id",
  "hidden": false,
  "power": 5,
  "skills": ["开端时已会的武学id"],
  "persona": "性情，不超过60字",
  "appearance": "外貌，不超过40字",
  "speech": "说话风格、自称、口头禅，不超过40字",
  "agenda": "开端时心中所图，不超过30字，无则null",
  "src": "第1回"
}]
```
说明：开端时已死但在剧情中被提及、且与隐情相关的人物（如有）也要收录，`status` 写 `dead`。`hidden: true` 表示此人虽在该地却不为人所见（潜伏、隐居、闭关、易容藏身）。

#### `05_items.json` —— 器物
```json
[{
  "id": "北冥神功卷轴",
  "kind": "兵刃|秘籍|药物|毒物|信物|宝物|杂物",
  "desc": "不超过60字",
  "location": "开端时所在地点id，若在人身上则为null",
  "holder": "开端时持有者人物id，若不在人身上则为null",
  "hidden": true,
  "hint": "若被藏匿：藏在何处、原著中如何被发现，不超过50字；否则null",
  "grants": {"skill": "武学id", "power": 30},
  "effect": "若为药物/毒物/宝物：效用，不超过40字；否则null",
  "src": "第2回"
}]
```
`grants` 仅秘籍类填写：研习后可得的武学，以及功力增益（按上面的度量衡估算）；非秘籍为 null。

#### `06_skills.json` —— 武学
```json
[{
  "id": "凌波微步",
  "school": "门派id或null",
  "type": "内功|外功|掌法|指法|剑法|刀法|棍棒|暗器|轻功|阵法|毒术|医术|奇术",
  "tier": "不会武功|三流|二流|一流|绝顶（练成后的档位）",
  "desc": "招式或功效在原著中的具体表现，不超过60字，供描写战斗时引用",
  "requires": "修习前提或禁忌，不超过40字，无则null",
  "src": "第5回"
}]
```

#### `07_relations.json` —— 关系（故事开端时已存在的）
```json
[
  {"src": "段正淳", "dst": "段誉", "rel": "父子", "secret": false, "src_ref": "第7回"},
  {"src": "段延庆", "dst": "段誉", "rel": "生父", "secret": true, "revealed_by": "事件id", "src_ref": "第48回"}
]
```
范围：血缘、婚恋、师徒、同门、主仆、结义、恩怨、仇杀、效忠等一切影响人物行为的关系；人物与门派的从属已由 `faction` 表达，不必重复。`rel` 用不超过8字的中文短语，方向从 `src` 指向 `dst`。开端后才形成的关系，写进事件的 `effects`，不要放在这里。隐情须写明 `revealed_by`（揭开它的原著事件 id）。

#### `08_canon.json` —— 原著事件时间线（最重要）
```json
[{
  "id": "聚贤庄之战",
  "order": 57,
  "when": "元祐七年八月",
  "where": "聚贤庄",
  "weight": 2,
  "actors": ["乔峰", "阿朱", "游骥", "游驹"],
  "requires": [["乔峰", "status", "alive"], ["阿朱", "status", "wounded"]],
  "summary": "不超过60字的客观史笔",
  "effects": [
    {"op": "set", "id": "游骥", "key": "status", "value": "dead"},
    {"op": "set", "id": "乔峰", "key": "location", "value": "雁门关"},
    {"op": "link", "src": "乔峰", "dst": "阿朱", "rel": "相恋"},
    {"op": "reveal", "src": "某人", "dst": "某人", "rel": "某隐情"}
  ],
  "src": "第19回"
}]
```
- **粒度**：凡是改变了世界状态的情节都是一个事件：人物死亡、受伤、迁移、身份变化、门派易主、器物易手、习得武学、关系建立或破裂、隐情揭开。纯对话、纯心理描写不算。预计全书 100~200 个事件。
- **weight**：江湖震动、天下皆知的大事记 2，局部事件记 1。
- **actors**：事件中起作用的人物 id（地点不算）。
- **requires**：该事件按原著发生所**必需**的前提，用 `[id, 属性, 期望值]` 三元组；只写真正必要的（关键人物活着、关键物件在某人手上等），通常 1~3 条。
- **effects**：事件造成的全部状态变化，只能使用以下 7 种指令，`id` 必须是已登记的 id：
  - `{"op":"set","id":…,"key":…,"value":…}`：key 可为 status / location / title / faction / power / hidden / state / holder（器物换主时 id 为器物）
  - `{"op":"add","id":…,"key":"power","value":增减}`
  - `{"op":"push","id":人物,"key":"skills","value":武学id}`（习得武学）／`{"op":"pull",…}`（失去）
  - `{"op":"link"/"unlink","src":…,"dst":…,"rel":…,"secret":可选}`（关系建立/破裂）
  - `{"op":"reveal","src":…,"dst":…,"rel":…}`（在该事件中被当众揭开的隐情，须与 07 中 secret 关系对应）
- **status** 只能取 `alive`、`wounded`、`dead`。

### 四、工作流程（请严格分步）

1. **第一步**：通读全书，输出 `meta.json` 与 `00_index.json`。此后各步只能引用索引中的 id；若发现遗漏，先补进索引并说明。
2. **第二步**：输出 `01_locations.json`、`02_roads.json`、`03_factions.json`。
3. **第三步**：输出 `04_persons.json`。若人数过多可分批，按 `00_index.json` 中的顺序续写。
4. **第四步**：输出 `05_items.json`、`06_skills.json`、`07_relations.json`。
5. **第五步**：按回目分批输出 `08_canon.json`（如第1~10回、第11~20回……），`order` 跨批连续编号。
6. **第六步：自检**，逐条确认后附一份问题清单：
   - 所有引用的 id 都在 `00_index.json` 中；
   - 道路图连通，每个子区域都与其 parent 相通；
   - 初始状态中没有混入开端之后才发生的变化；
   - 每条 secret 关系都有对应的 `reveal` 事件，或明确说明原著中未被揭开；
   - 同一人物的 power 与锚点尺度一致；
   - 事件按 `order` 排列后，每个事件的 `requires` 在其之前的状态下能够成立。

### 五、输出要求

- 每个文件只输出纯 JSON，不加注释、不加 markdown 代码块标记，UTF-8 编码。
- 文件过长需分段时，在分段处注明「续接」，下一段直接接续数组元素，不要重复已输出的条目。
