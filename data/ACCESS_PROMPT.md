# 《天龙八部》通行条件补充提示词

> 用法：把下方「提示词正文」连同 `data/canon/` 中的 `00_index.json`、`01_locations.json`、`02_roads.json`、
> `05_items.json`、`06_skills.json`、`08_canon.json` 一并交给持有原著全文的 AI（最好是上一轮抽取的同一个对话）。
> 产出 `14_access.json` 与 `15_roads_patch.json` 两个文件，放回 `data/canon/`。

---

## 提示词正文

你此前已从《天龙八部》世纪新修版中抽取了地点（01）与道路（02）。现在的道路只表示"两地相通"，但原著中许多通路并非想走就能走：悬崖只能坠下不能攀上，琅嬛福地的石门须发现机关，曼陀山庄须乘船、擅入者遭严惩，擂鼓山木屋须破解珍珑方得入内，缥缈峰须过断崖铁索……

请依据原著，为**不能无条件通行的通路**补充通行条件，并修正道路表中不合原著的捷径。

### 一、总原则

1. **只取原著事实。** 原著明写的通行方式照录；需要推断的条目加 `"inferred": true`。
2. **只用已登记的 id。** 地点、器物、武学、人物、事件 id 必须来自 `00_index.json`。主角统一写作 `"player"`。
3. **有向。** 每一条通行条件只描述一个方向（from → to）。反方向若条件不同，另写一条；反方向若根本走不通，也要单独写一条并标 `"blocked": true`。
4. **只写受限的通路。** 自由来往的道路不必列出。
5. **简洁。** 字段严格遵守字数上限。
6. **出处。** 每条带 `"src": "第N回"`。

### 二、`14_access.json` —— 通行条件

```json
[
  {
    "from": "无量山·山崖",
    "to": "无量山·谷底",
    "kind": "悬崖",
    "blocked": false,
    "hidden": false,
    "how": "原著中如何通过，不超过40字",
    "requires": [],
    "risk": "失败的后果或通过的代价，不超过30字",
    "src": "第2回"
  },
  {
    "from": "无量山·谷底",
    "to": "无量山·山崖",
    "kind": "悬崖",
    "blocked": true,
    "hidden": false,
    "how": "峭壁无可攀援，原著中段誉另寻出路",
    "requires": [],
    "risk": null,
    "src": "第2回"
  }
]
```

字段说明：

| 字段 | 含义 |
|---|---|
| `kind` | 从下列类型中选一个：`悬崖` `险径` `机关` `秘道` `水路` `潜入` `守卫` `禁地` `阵法` `其他` |
| `blocked` | `true` 表示此方向在原著中凡人无法通行（除非剧情另有奇遇，由游戏导演临场裁定） |
| `hidden` | `true` 表示此通路本身是秘密，主角须先发现才知道它存在（如隐门、地道、暗格后的密室） |
| `how` | 原著中人物实际如何通过，供游戏导演在剧情中兑现 |
| `requires` | **可由系统硬性判定**的前提，用 `[id, 属性, 期望值]` 三元组，可为空。可用的写法：<br>`["player", "skills", "武学id"]` 主角须会某武学<br>`["player", "inventory", "器物id"]` 主角须持有某器物<br>`["地点或景物id", "state", 值]` 某处须处于某状态（如机关已开）<br>`["人物id", "status", "dead"]` 某人须已死（如守关者）<br>拿不准能否硬性判定的条件（如"须有人引路""须获主人许可"），写进 `how`，不要写进 `requires` |
| `risk` | 强闯或失败的代价，如"坠崖重伤""被王夫人斩去手足"；无则 null |

覆盖范围（至少包括以下各处，并通读全书补齐其余）：
- 无量山：山崖与谷底、谷底与琅嬛福地的隐门、琅嬛福地内各石室之间；
- 万劫谷：谷口誓碑、石屋、地道；
- 大理：天龙寺牟尼堂、皇宫；
- 江南：燕子坞、琴韵小筑、听香水榭、曼陀山庄、琅嬛玉洞（水路、引路、禁入）；
- 少林寺：藏经阁、菩提院等禁地与守卫；
- 擂鼓山：珍珑棋局与木屋；
- 天山：缥缈峰、灵鹫宫、断崖铁索、各关卡；
- 西夏：皇宫、冰窖；
- 辽国、雁门关等边境关隘；
- 星宿海、聋哑谷等门派驻地；
- 任何原著中出现过机关、阵法、密道、暗门、渡口的地方。

### 三、`15_roads_patch.json` —— 道路修正

现有道路表中，为表示"子区域属于某处"，许多子区域之间以 0 日相连，经由中枢节点（如「无量山」）会形成原著中不存在的捷径。例如从「剑湖宫」经「无量山」0 日即可到达「琅嬛福地」，而原著中须坠崖方能抵达。

请逐一检查全部 0 日道路与经由中枢节点的路径，按原著实际地理修正：

```json
{
  "remove": [["无量山", "琅嬛福地"]],
  "add": [["无量山·谷底", "琅嬛福地", 0]],
  "change": [["剑湖宫", "大理城", 4]],
  "notes": ["每处修改的理由，不超过40字，带回目"]
}
```

- `remove`：删除的道路（两端 id，顺序不限）。
- `add`：新增的道路 `[id, id, 步行日数]`，两端必须是已登记地点。
- `change`：修改日数的道路 `[id, id, 新的步行日数]`。路程一律按**步行**估算，游戏会统一换算为骑马。
- 修正后全图仍须连通（受限通路也算连通，通行条件另由 14 规定）。
- 如确需新增地点，在 `notes` 中说明，并按 `01_locations.json` 的格式另附 `new_locations` 数组，同时补入索引。

### 四、自检（逐条确认后附问题清单）

- 14 中每条的 `from`、`to` 都是已登记地点，且两地在修正后的道路表中直接相连；
- 每处单向通路（悬崖、陷坑、冰窖坠入等）的反方向都有一条 `blocked: true` 或另有条件的条目；
- `requires` 只引用已登记的 id，且原著中至少有一人在相应时刻满足了它（否则原著剧情本身就过不去）；
- `hidden: true` 的通路在原著中确有"被发现"的情节，回目可查；
- 15 修改后，原著事件（08）中每个人物的移动，按事件顺序在道路图上都可达。

### 五、输出要求

- 两个文件各自只输出纯 JSON，不加注释、不加 markdown 代码块标记，UTF-8 编码。
- 过长需分段时注明「续接」，下一段直接接续，不重复已输出的条目。
