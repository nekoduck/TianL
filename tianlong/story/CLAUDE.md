# story/
> L2 | 父级: /tianlong/CLAUDE.md

故事层(v4)。宪法第 14 条「故事也有账」的落地：world/ 记住发生过什么，story/ 记住故事走到了哪里——场、时限、原著窗口、主角线、伏笔、选项槽位都是有写入者、有读者、会自动变化的状态，存在玩家黑板上、随存档走；LLM 在这些结构里创作，不负责记住结构。全部是确定性的纯规则，不调 LLM，不增加调用次数。
依赖方向：story → world(只读，加上黑板上的故事账)；engine 读 story 并把场记作为文字交给 narrative(gm["brief"])；world 与 narrative 都不 import story。

成员清单
timing.py: 时间是后果——claim 由规则主张戏内光阴的下限(研习一部秘籍到下一阶的合理时长：初窥一个时辰、此后每回两个时辰；求教两个时辰；不在险境时歇息养伤半日；玩家所选是「此后」之举至少一顿饭)，引擎取它与导演措辞的较大者；cut_minutes 把幕间省略换成分钟——一段长度(一顿饭/半日/一夜/一日)或「到某一刻」(入夜/天明/正午，或 stakes 里的某个时限，至多两日)
canon.py: 原著窗口——ready/pull 是窗口的「拉」：主角就在事发之地、相关者都在身边、前提未破、按 order 之前没有牵涉同一批人且前提未破的原著悬着，PULL 日内将至的那一桩今天即可上演(推仍归 lod.split_due)；consume 是消费：导演已成立的后果与 WITHIN 日内某桩未演原著的签名(先比擒放、生死、易手，没有这些才比人物去向)过半重合即记作兑现，不再到期、不交史官；只记账、不改物理
stakes.py: 时限账——导演在顶层 clock 里立下的期限 {id, what, due, turn}，至多 CAP 个；due 在到期那一回合交出并除去(交场记一次)，urgent/left 给场记与选项的「最急的一件事还剩多久」，due_at 让 cut 可以等到某个时限
scene.py: 场——叙事的基本单位，跨回合：{id, where 地点簇, ask 问题, state 开/转/合/断, turns, tried 试过的路数}；begin 在上一场合了、断了或主角走出地点簇时开新场，close 按裁决之后的本幕之问推进(场况与本幕之问一一对应：合=resolved、断=interrupted、开转=open)，演满 CAP 回合未合即要求收场(取代 v3 的僵持检测)，tension 由场况推出
brief.py: 戏剧调度器与场记——compose 确定性地选出本回合的主干(此地上演的原著 > 到期的时限 > 该埋的系统伏笔 > 主角线与在场之人的图谋轮流 > 顺着主角的举动推进本场之问)，写成导演上下文的第一节(场况与问题、赌注、主干、回收、已试路数、主角线、此后之举略写、收场提示、光阴)；allow_pull 轮转：原著连占三场主干就不再提前拉原著；remember 记下主干来源
arc.py: 主角线——出身的所求升格为 起意→入局→受挫→抉择→了结，按所求的类别(求武学/挣名字/护人)由已成立的事实推进、只进不退；受挫后一回合即提示抉择，了结时请导演 set player goal 提一条新的所求，goal 一变即从起意重开
setups.py: 系统伏笔——隐情的揭示事件 HORIZON 日内将至、当事人就在身边，场记请导演让他露出一点端倪(同一条至多 TIMES 回、不得说破)；揭示事件正在此地上演即列为回收；编剧随手写的悬念仍归引擎的 hooks
choices.py: 选项槽位——slots 给编剧三个槽：A 此刻(换一种没试过的路数推进本场之问)、B 此后(一件持续之事或过场，写出代价；险境里改为脱身)、C 机缘(时限、图谋里的两难或机会)；later 给此后槽的兜底项(续行、研习手边的秘籍、带伤歇息、一条远些的出路)，供 world/menu 补位；编剧标在选项上的尺度由引擎记下，玩家选了此后，下一回合略写、时长按那件事结算
__init__.py: 包标记，空
