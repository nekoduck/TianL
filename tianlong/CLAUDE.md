# tianlong/
> L2 | 父级: /CLAUDE.md

游戏本体。三层一线：`world/` 掌管世界（地理、器物、人物、时间、账本、原著日程、情境）并替剧情记忆、算账、裁决、送信、结算——它是唯一的事实源与裁判(v6：玩家读到的正文是每回合的定本，world/settle 把它交世界复核入账，账本是正文经裁决的投影)；`story/` 记住故事走到了哪里（场、时限、原著窗口、主角线、伏笔、选项槽位），每回合给导演一份场记；`narrative/` 提议剧情、成文、拟选项；`engine.py` 是它们唯一的交汇处：LLM 提议，世界裁决，文字只渲染已成立之事。

成员清单
world/: 基础设施——图数据库、时钟、黑板、双账本与消息队列、剧情落账 DSL、情境层、数值规则、裁决器与变化词表、选项出口检查、通行裁判、LOD 调度、GraphRAG 视锥与导演后台（见 world/CLAUDE.md）
story/: 故事层(v4)——时间结算(规则主张时长、cut 等到某一刻)、原著窗口(拉与消费)、时限、场、场记与主干调度、主角线、系统伏笔、选项槽位（见 story/CLAUDE.md）
narrative/: 剧情层——Gemini 网关、提示词与叙事纲领、导演(含返工)/编剧/书记/推演/史官 Agent（见 narrative/CLAUDE.md）
engine.py: 游戏主循环 Game(v6 账文同构：正文经 settle.Gate 出闸——段里报了姓名先入账、再按说话人过掩码，放行即存档；随后结算——账房读定本与账本快照开出账上缺的变化，settle.commit 核据、只收叙述成立得了的事、经 effects 入账并入本回合 applied，规则之事、落不了的与词表查出的记作账文分歧 drift 交下回合导演，有分歧时梗概与传言以系统核实过的后果代记，身况结算之后重算；此地原著的亲历以回合开始的所在为准；选项也过视角掩码)(v4：回合开始先结远方原著、窗口拉起将至的此地原著(原著连占三场主干则不拉)、到期的时限、续场或开场、推进主角线，story/brief 写成场记放在导演上下文第一节；导演报场况 scene(开/转/合/断)，引擎译成本幕之问交裁决；戏内光阴取措辞与 story/timing 规则主张的较大者，cut 可等到入夜或某个时限；落账后按签名把导演演掉的原著记作兑现、记下导演立的时限；编剧拿到三个选项槽位，引擎记下所选之举的尺度(此后即下一回合略写)；编剧写出账上没有的进境、得失、去留、生死、擒放(adjudicate.afterword)记作 drift 交下回合导演；收尾推进场与主角线、记下主干来源；act 原话照收；一回合原子——中途抛错则世界与记忆回到回合开始；flush 汇合后台折叠的梗概)，串起"授意(选项自带的对象+原话里的名字)→先了远方到期原著→焦点检索与后台→导演逐拍提议→在世界副本上试演(逐拍落账→此地原著(导演挪动过的人原著挪不动)→词表体检)，硬违例返工一次、仍不成立的拍整拍作废→定稿落账→时长按措辞与走得通的道路结算(研习至少一顿饭)，无人相逼、本幕未被打断时幕间省略再跳过光阴(pacing.calm 把关；歇满两个时辰按规则养伤)→传闻→编剧从主角视角(perspective.veil/mask：不识名之人只剩叫法；成文按段再过一遍 mask)只凭已成立之事成文并拟选项伏笔(场外推演与新到期的远方原著在成文与选项验收之后进行，v5：编剧、掩码与验收看的是同一个世界)→选项过出口检查、对象记作下一回合授意→事件门槛入江湖账本→近事、未了之事推进与了结、伏笔账(至多两条，身体不作伏笔)、节奏账(pacing)、场景实体回收，近事溢出交后台折叠梗概"；节奏看本幕之问的结局(连番被打断则不得再打断)；v5 一人一主：主角眼前的原著(此地、近旁，或当其时要把身边之人带走的)交导演、其相关者若在这一片即上眼前的名册(把人带去别处的那一桩，主角只看见人走、不记亲历，事本身随传闻抵达)、戏内光阴只按会成立的拍主张、抵达即遭遇(编剧得知到了之后眼前有谁)、亲见与传闻出内核前过视角掩码、近事以「你」称主角、合要有账可依(scene.close 的 settled)、轻描淡写的态度 link 不算江湖大事、partial 落账(导演挪动过的人原著挪不动)，场外推演只推自由之人(没有就不调模型)，史官看得见相关者此后的原著；回合产物为结构化纯 dict(历法分段/身况标签/亲见与传闻)；可选监听逐步报告 stage→head(快照，选项为空)→text 增量(按段送出)；附双账本对照 debug 视图
protocol.py: 前后端契约 tianlong/1.3 的 Python 实现(1.3：选项随 done 放出，head 的 options 为空)——present 把引擎回合译成载荷(选项编号带回合序以识破过期)、relay 把引擎进度译成流式事件、resolve 把行动译回引擎原话(写明的卷与回合须与眼下一致，否则 409 stale_turn)、ProtocolError 携带 HTTP 状态与错误码；契约正文在 web/PROTOCOL.md
server.py: 传输层——标准库 ThreadingHTTPServer 托管 web/ 静态前端与 /api/session(续读/开卷)、/api/action(行动)；POST 只收同源 JSON(跨站 403)、Content-Length 须为非负整数；Accept 含 text/event-stream 时以 SSE 推送(首事件才开流，之前的错误仍为 JSON；读者离席回合照写)；Hub 单机单局、一锁一笔(忙则 409)、每回合自动存档(终端存档格式 + web 段)，Session 可开卷/续卷(续卷记得上回合末段)；开流前后读者离席都不打断回合；不含游戏逻辑
cli.py: 终端表现层，选名号与出身、展示正文/亲见与传闻/身况标签/验收过的 3 个选项，处理自由输入(半角数字即第几个选项，此快捷写法只在终端；说书人失声即提示重试，世界已回到回合开始)与 /save(先汇合后台梗概) /load /me /debug 指令(读档失败只提示、不丢眼前这一局)，读取 .env；--web 时改为启动 server 并续读 --load 存档或上次的自动存档(坏档不覆盖)，--trace 记录大模型调用
__init__.py: 包标记，空

依赖方向: cli → (server → protocol) → engine → (narrative → world.rag 只读) + (story → world) + world；world 不依赖任何上层，narrative 不 import story(场记以文字经 gm 交给它)，engine 不知道 protocol 的存在
