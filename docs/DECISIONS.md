## 二、计划没写明、实现时选定的事项

* **定义文件格式用 TOML**（计划 6.2 的示例是 YAML 风格）。理由：只用标准库，`tomllib` 自 3.11 起内置，无需自写解析器；
  语义与计划示例一一对应（`who/when/do` 三段）。代价：TOML 裸键不接受中文，所以**键用 ASCII，中文放值里**。
* **随机数口径**：内核与集成世界用 v0.2 的 sha256 计数器式随机数；`rnd_b2`（blake2b）只为复现 `npc_spike.py` 原型哈希而保留。
* **运行时场所钥匙是 `code`**（如 `SH_LIBRARY`），定义编号只用于定义间引用。这样 B1 迁移后数据库里的场所字符串不变，v0.2 基准哈希才能保持。
* **时间指针**：内核新增 `begin_day / run_slot / end_day / advance`，`step()` 是三者的组合，未接引擎时与原型逐位相同。
* **工作分支**：按用户指示直接在 `realTLL-empty` 上开发（该分支只有一个空的初始化提交），不读取、不合并其他分支。
* **半餐（耦合 a）次日生效**：内核每日消耗阶段在 `begin_day` 里、早于时辰 tick，所以引擎当日判出的半餐，内核粮账要到次日才扣减（引擎在 `end_day(d)` 里为 `d+1` 登记，登记当日抛 `ValueError`）。取这个而不是把消耗挪到日末，理由：挪动会改变游方僧离寺的时点与 `where` 的日内历史，牵动 B1 已逐位对照过的分支；而一次半餐在粮账上只差约半日口粮，晚一日记账不改变任何守恒与不变量（量级没有实测，留给 C1 的经济中立性与偏差验收去量）。引擎自己的“饥”当日就按半餐算。若 C1 集成验收发现经济偏差，再改契约（ARCHITECTURE 5.1 与 6.1 第 3 步同步改）。
* **core 不带任何一座寺院的历法**：`tianl/core/calendar.py` 的默认历法改为从 `defs/calendar/shaolin.toml` 懒读（`DEFAULT_CALENDAR`），删去代码里的节日表与收成日缺省；NPC 引擎已不用这一份：它的历法是规格的一部分，来自 defs 里 `rule:<scope>:schedule` 的 `calendar` 字段（原型场景引用 `calendar:shaolin:main`），换 scope 就换历法（见 NPC_ENGINE 12.2）；模块级 `cal()` 现在只剩内核之外的零星调用。

## 三、原文（已提供）与处理

用户在会话中提供了《天龙八部》文本（三联版，50 回，GB18030 编码、CRLF、带论坛水印行，约 128 万字）。处理方式：

* **只存本地**：转成 UTF-8/LF 放在 `sources/tianlong.txt`，被 `.gitignore` 忽略，永不提交（计划 3.1 第 2 条）。仓库里只存指针（回、段、段内起止字位、段落哈希）、提及计数与文本清单（`data/canon/text_manifest.json`，只有哈希与计数，没有文字）。
* **仓库内不得出现原著原文**：证据只存指针，不存引文；`tests/test_no_text_leak.py` 随机抽取原文中的长片段，断言它们不出现在任何入库文件里。
* **章回约定**：第 0 回 = 卷首（“新序”“释名”），第 1–50 回 = 正文（标题形如“一 青衫磊落险峰行”），第 51 回 = 后记，第 52 回 = 附录；水印与分隔行在规范化时去除。
* **抽取方式**：第 3–4 阶段按回做滑动窗口抽取，每条断言带原文指针（`basis = text`），再由另一批代理逐条复核“这段原文是否支持这条断言”。凭记忆补的断言（缺口填补、开局状态推断）仍标 `basis = recall` 或 `tag = infer`（须写理由），验收时分开统计。
* 抽样精度、证据指针有效率现在有了可统计的分母；仍然是模型代理做判断（计划里的“人工复核”由独立代理代替），报告里会写明这一点。
* 凭记忆抽取的内容在细节处仍可能有误；缺口清单（`docs/GAPS.md`）逐项标了填补办法与待核标记。
