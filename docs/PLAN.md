# 《天龙世界》终极计划：从原著到世界，再到像真人的 NPC

Nov 10, 2026 · @xinyugf

## 一页结论

计划分三步：把原著变成可回查的断言表，把少林寺的做法推广成全图的非人基座，再用九层取自已发售游戏的机制搭出不靠 LLM 的 NPC。第三步的核心我用一个 60 人的原型跑过了；前两步是设计，还没有跑。

| 步 | 产出 | 借鉴 | 状态 |
| --- | --- | --- | --- |
| 一、原著 → 数据 | 断言表、开局快照、情节事件库、缺口清单 | Wikidata 的陈述模型 | 设计，未跑 |
| 二、非人基座 | 十类定义、设施目录、六种组织原型、全图骨架 | v0.2 少林寺；《模拟人生》的智能物件 | 少林寺已跑，其余是设计 |
| 三、NPC | 九层：档案、行为包栈、需求、设施、工作、见闻、规矩、好恶、一生 | 13 部作品，逐项对照见第 2 节 | 第 2 到 8 层的核心逻辑已由原型跑过 |

原型的四个结果：

- 60 人、30 日、21,600 次决定，每次约 6 微秒。重跑哈希一致；观察者换位置，不改变任何人的决定。
- 一条完整的因果链自己跑了出来。馋而散漫的虚真一个月偷食 7 次，前 5 次成了悬案，第 6 次被巡夜撞见，次日当众罚跪香；延长到 90 日，他被迁单出寺。
- 一件没人举报的事，19 天传到 59 人中的 40 人，月末只剩 22 人还记得。
- 同一场厨房减员，有人代理则无事发生，无人代理则偷食 58 起、处分 45 起。

原型还纠正了六处纸面上看不出的设计错误，见 10.2。

没跑过的部分，请按设计稿对待：原著抽取流水线、全图骨架、差事步骤走命令通道、易容与谎言下的认知、人生脉冲、心情的后两道线、结伴出行、落到 SQLite 后的性能。

需要你定的有八件事，在第 13 节。最要紧的是第 1 件：原著情节要不要按书上演。

## 1 前提与假设

本计划只做数据与内核。运行时的 NPC 不用 LLM，控制台是唯一的观察与游玩窗口。

### 1.1 沿用少林寺 v0.2 的内核

《天龙世界》少林寺世界基座 · 实现方案 v0.2 的内核原样保留，本计划只在它上面加东西。

| v0.2 已有 | 在本计划里的作用 |
| --- | --- |
| 命令 → 校验 → 事件 → 状态 | NPC 和玩家走同一条命令通道 |
| 每日九阶段 + 事件队列 | 在其中加入十二时辰循环 |
| 规则 → 需求 → 差事 | 直接成为 NPC 的工作板 |
| 作息是函数，班表每日物化 | 升级为行为包栈 |
| 物理与规范两层校验 | NPC 自己也会犯规，并被同一套规矩处理 |
| 事件日志 + 见证人 | 感知、记忆、传闻共用的唯一数据源 |
| 抽象阶梯 | 人口按需生成，模拟精度分档 |
| 确定性、守恒、每日不变量 | 全部继续适用 |

### 1.2 “不发明”怎么落实

每个 NPC 机制都写明四样：出处、原样借用的部分、我们的调整、证据链接。找不到出处的“胶水”在第 2 节单独列出，方便你逐条审。

### 1.3 GPT 调查怎么用

调查文件在第 477 行中断，停在《Shadows of Doubt》一节的半句话上。开头承诺的《矮人要塞》《RimWorld》和“与 LLM 共存的架构”三部分没有出现。

我采用它的作品清单和证据分级，逐条核对了引用，核对结果在第 14 节。缺的三部分由我按公开资料补齐。

### 1.4 默认假设

以下七条我先按默认值推进，第 13 节请你确认。

1. 建造期可以用 LLM 做原著抽取，运行期的 NPC 不用。
2. 原著情节编成条件事件库。沙盒模式下条件满足才触发，另设“按书重放”模式专门用来验收。
3. 开局时刻取原著第一回之前。
4. 版本以你提供的文本为准，默认三联版。
5. 全局时间单位是时辰，只有观察者所在的场所细分到刻。
6. 玩家也是世界里的一个人，只是操纵者不同。
7. 打斗只做结果级结算，不做招式数值。

### 2.2 没有出处的胶水

以下五样不来自任何一部游戏，是工程上的连接件，请单独审。

1. 计数器式随机数：每次抽签由种子、用途、日期、时辰、人共同决定。v0.2 已有。
2. 证据指针：原著抽取的每条数据都指回原文位置。
3. 观察者无关测试：观察者站在哪里，都不改变任何人的决定。
4. 需求惰性求值：没人看的时候不逐时辰更新，读取时按经过的时间补算。
5. 玩家、程序、LLM 三种操纵者共用同一条命令通道。

### 2.3 GPT 调查：一处不采用，一条提醒照守

- 不采用：调查把《天国：拯救》写成“GOAP 加模块化行为树”。Warhorse 自己的[论文](https://arxiv.org/pdf/1508.00377.pdf)和 [GDC 讲题](https://schedule.gdconf.com/session/supporting-thousands-of-npcs-in-kingdom-come-deliverance-kingdom-come-deliverance-ii/915120)只讲行为树、智能物件、智能区域和精度分档。我没有找到 GOAP 的出处。
- 照守：调查自己提醒过，《潜行者》访谈里那些更丰富的贸易和探索行为并未全部进入正式游戏。本方案只借两样确已发售的东西：在线与离线两档，和智能区域派活。

## 3 第一步：原著 → 数据

抽取的产物是一张可回查的断言表，不是一本设定集。每条断言带原文位置、说话人和可信等级；游戏库里不存原文。

### 3.1 四条规矩

1. 内核要什么字段，才抽什么。属性清单是封闭的，由第 4、5 节的表结构反推。
2. 原文留在本地的源文本库。游戏库只存指针：回、段、起止字位、段落哈希。
3. 人物嘴里说的事，只记成“某人这么说过”，不直接当事实。
4. 真相和各人的认知分两处存。谁知道什么，本身就是数据。

第 3、4 条是这部书的特殊要求。易容、化名、谎言和三十年前的旧案撑起了大半情节；把人物的话当事实抽，世界从第一天起就是错的。

### 3.2 九个阶段

| 阶段 | 做什么 | 产物 | 机器校验 |
| --- | --- | --- | --- |
| 0 规范化 | 统一编码，切成回、段、句，编稳定编号 | 源文本库 | 段落哈希可复算 |
| 1 提及普查 | 逐回列出人物、地点、组织、物、武学、称号的每次出现 | 提及表 | 按字位能在原文取回同样的字 |
| 2 消歧合并 | 把别名、称呼、易容后的身份归到同一实体 | 实体表、别名表、“以某身份出现”表 | 同一段内一个称呼只指一个实体 |
| 3 断言抽取 | 滑动窗口逐段抽取带类型的断言 | 断言表 | 属性在封闭清单内；主语宾语都是已登记实体 |
| 4 复核 | 第二遍只做判断：这段原文是否支持这条断言 | 支持、不支持、存疑 | 不支持的不进入下一步 |
| 5 时间线 | 把相对时间整理成事件的先后与区间 | 事件表、先后关系 | 无环；无人同时在两地；死后不再出场 |
| 6 裁决 | 给冲突的断言排等级，定不了的进人工队列 | 断言等级、待审队列 | 每条“首选”断言至少一条证据 |
| 7 缺口清单 | 逐表逐字段标出原著没给的 | 缺口表及填补办法 | 内核必填字段全部有来源标签 |
| 8 编译 | 输出定义文件、开局快照、情节事件库、标准问答集 | defs、snapshot、events、qa | 引用完整；内核能加载 |

第 3、4 阶段可以用 LLM，其余阶段是普通程序。模型可以换，流水线只认 JSON 结构和机器校验。全书五十回、一百多万字，确切规模以第 0 阶段的统计为准。

### 3.3 断言表的结构

结构照搬 [Wikidata 的陈述模型](https://en.wikipedia.org/wiki/Wikidata)：一条陈述是主体、属性、值，外加限定词、出处和等级。它[允许互相矛盾的陈述并存](https://blog.wikimedia.de/?p=15735)，用等级区分，正好用来装一部充满谎言的小说。

| 字段 | 含义 | 例 |
| --- | --- | --- |
| subject、property、value | 谁的什么是什么 | 人物甲 · 师父 · 人物乙 |
| qualifiers | 限定词：起止时间、地点、说话人、叙述方式 | 说话人 = 人物丙；叙述方式 = 人物之口 |
| rank | 首选、普通、作废 | 后文揭穿的说法标为作废，保留不删 |
| evidence | 原文位置，可多条 | 回、段、起止字位、段落哈希 |
| source\_tag | 原著明文、原著推断、史料先验、种子生成 | 推断必须写理由 |
| reviewed | 机器复核结果与人工复核人 |  |

叙述方式分四种：叙述者陈述、人物之口、回忆、传闻。裁决的默认次序是：叙述者陈述高于多人一致的说法，多人一致高于单人说法；后文揭穿的真相高于早先的表象。

### 3.4 抽哪些属性

| 实体 | 属性（封闭清单） | 喂给 |
| --- | --- | --- |
| 人物 | 姓名、别名、性别、年龄线索、籍贯、门派与辈分、职位、亲属、师承、结义、仇怨、性格词、志向、会的武学及高下描述、持有物、说话特征标签 | 档案、关系、性格、认知 |
| 地点 | 名称、上下级、相邻与路程描述、归属、功能、出入限制 | 地点树、路线 |
| 组织 | 名称、类型、层级与职位、规矩与处罚、据点、与别派的关系 | 组织、岗位、规范 |
| 物 | 名称、类别、归属与转手、藏处、功用 | 独有物、文书 |
| 武学 | 名称、所属、传授限制、相克与禁忌、谁会 | 武学条目 |
| 事件 | 参与者及角色、地点、时间区间、前提、结果 | 情节事件库 |
| 认知 | 谁在何时得知何事、信的是真是假、从谁那里得知 | 秘密登记、各人见闻 |

说话特征只抽成标签，如“文绉绉”“自称老衲”，不存对白原文。它留给以后的 LLM 人设用。

### 3.5 原著没给的怎么办

原著给得出人物、关系、地名和规矩，给不出粮价、人口、作息和多数无名之人。缺口清单逐项写明填补办法，只有三种。

- 史料先验：如《禅苑清规》的职事、宋代的物价与路程。
- 种子生成：如三百僧众里无名的那些人。
- 问你：前两种都定不了、又影响玩法的，进待确认清单。

少林寺 v0.2 已经这样做过一遍，它附录里的“原著与史料锚点”就是这张表的前身。

### 3.6 验收

| 检查 | 通过线 |
| --- | --- |
| 证据指针有效 | 100% 能在原文取回 |
| 抽样精度 | 随机 200 条首选断言，人工判对不低于 95% |
| 召回 | 你点名的 30 个人物，门派、师承、亲属无一缺漏 |
| 时间线自洽 | 无环；无人同时在两地；路程够走 |
| 按书重放 | 把情节事件库按时间线灌进世界，不违反任何物理规则 |
| 待审队列 | 已激活区域内清零 |

“按书重放”是这一步最硬的检验。书里某人三日从甲地赶到乙地，而路线表算出来要十日，那么不是抽错了，就是路线表错了。

## 4 第二步：非人元素的基座

非人元素先铺一张全图骨架，再一处一处展开。少林寺是第一处，已经跑通；每处展开时交付的清单相同，所以从第二处起主要是填数据。

### 4.1 定义、实例、状态分开

| 类 | 是什么 | 存哪 | 例 |
| --- | --- | --- | --- |
| 定义 | 一类东西的模板，开局后不变 | defs 目录下的文本文件，进版本库 | “禅床”这种设施；“典座”这个职位 |

| 状态 | 随时间变的量 | world.sqlite | 这张床此刻谁在用；库里还有几石米 |

定义可以继承：写一个 parent，再写要覆盖的字段。所有引用用稳定编号，形如 `place:shaolin:cangjingge`，加载时做引用完整性检查。

### 4.3 设施与交互：给 NPC 准备的世界

这是本步新增最多的一类。按《模拟人生》的做法，“能做什么”写在设施上，不写在人身上；加一种设施，所有人立刻会用。

| 设施 | 工位 | 广告（满足什么） | 准入 | 记账 |
| --- | --- | --- | --- | --- |
| 禅床 | 每人一张，归属到人 | 困 | 本人 | 无 |
| 斋堂座位 | 按僧数 | 饥、群 | 过堂时辰 | 厨房按实到人数出粮 |
| 灶 | 2 至 4 | 无，是工作位 | 厨房职事与代理 | 耗柴、水、粮 |
| 蒲团 | 按禅堂大小 | 志（禅）、困 | 全寺 | 无 |
| 经案 | 少 | 志（学） | 藏主在场 | 无 |
| 练武场 | 中 | 志（武）；耗困、洁 | 本寺僧人 | 无 |
| 浴位 | 按人数与频次反推 | 洁 | 开浴日 | 耗柴、水 |
| 井台 | 少 | 洁；另有挑水工位 | 全寺 | 出水 |
| 廊下 | 多 | 群 | 全寺；止语处除外 | 无 |
| 药柜、病床 | 少 | 病 | 堂主在场 | 耗药 |
| 茶座、客房（山下） | 中 | 饥、群、困 | 付钱 | 收钱入店铺账 |

每个交互的字段固定：所需工位、时长、需求增减、所需物与产出物、准入条件、触犯的规范。最后一项很关键：在厨房“取食”对饭头是工作，对旁人就是偷食，同一个交互有两种规范后果。

设施容量要按“人数 × 频次”反推。原型里浴室起初只有 6 个位，60 个人一个月轮不到一次，洁净需求全员贴地。

### 4.5 先铺全图，再逐处展开

地点有三档精度，和 v0.2 的抽象阶梯同构。

- 端口：只有名字、路程和一个边界账户。
- 节点：有人口批次、库存和收支，按日结算，不展开房间。
- 展开：有房间、设施、岗位、规矩，里面的人逐个模拟。

展开顺序：

1. 全图骨架。所有抽取到的地点先建成端口或节点，路线连通，跑十年不破守恒。
2. 少林寺。已展开，补上 4.3 的设施目录。
3. 第二原型：丐帮的一处分舵。
4. 第三原型：一处世家庄园。
5. 之后按“原著戏份多少”和“原型是否已有”排队。

每展开一处，交付同一张清单：地点树、设施、岗位与任命、规则、规范、账户与工序、独有物、开局人口、原著锚点、扰动实验。

### 4.6 秘密与文书

天龙世界里“谁知道什么”是硬数据。秘密登记表记录每件要紧的事：真相、开局时的知情人、各知情人信的版本、能证明它的物证。

文书是带内容的独有物，包括书信、秘籍、账簿、度牒。读到它，就得知相应的事。

NPC 的见闻（第 8 节）和这张表是同一套结构：开局时由它初始化，运行中由事件追加。

## 5 第三步之一：人是谁

每个被单独模拟的人有一份持久档案。连同日程和关系一起生成一个完整的人，是《看门狗：军团》Census 的做法；按需生成、生成后只升不降，是 v0.2 抽象阶梯的规则。

### 5.1 档案

| 组 | 字段 | 说明 |
| --- | --- | --- |
| 身份 | 编号、姓名与法名、别名、性别、生年、籍贯 | 来源标签逐字段记录 |
| 归属 | 组织、辈分、师父、岗位 | 岗位经任命表，人与岗位分离，沿用 v0.2 |
| 住与业 | 床位、常驻场所、修行或营生方向 | 床位是一件被认领的设施 |
| 身体 | 健康、伤病、五项需求的当前值 | 需求惰性求值 |
| 性格 | 五项刻度（0 到 100）与若干词条 | 见 9.1 |
| 本事 | 武学及层级、技艺 | 只分层级，不设战斗数值 |
| 认知 | 黑板记忆、见闻、对他人的好恶 | 见第 8、9 节 |
| 操纵者 | 程序、玩家或 LLM | 见第 11 节 |

### 5.2 三种来历

- 原著人物：由第一步的断言表直接装载。性格词映射成刻度，认知由秘密登记初始化。
- 生成个体：由种子生成。分布参数来自组织原型，比如寺院执事的“精进”“守戒”均值高于清众。
- 选角：事件需要一个“贪嘴的清众”时，先在已有的人里找合适的，找不到才新生成。不为剧情凭空造人。

原型里 60 人中有 3 个是手工指定的“要角”：一个馋而散漫，一个懒，一个刚正。其余 57 人全由种子生成，其中自然长出了另外三个精进偏低、会缺课的人。

### 5.3 什么时候把背景人变成个体

三种情况：玩家与他单独打了交道；他被选进某个事件；他被任命到岗位。变成个体后永不退回。

### 5.4 玩家

玩家是一份普通档案，只是操纵者一栏填“玩家”。所以玩家受同样的需求、规矩和传闻约束：夜里进厨房拿吃的，同样会被巡夜撞见。

## 6 第三步之二：这一时辰做什么

每人每个时辰只回答一个问题：我现在做什么。答案来自一摞按优先级排好的行为包，自上而下第一个成立的生效。这就是《上古卷轴 V》的 Package Stack。

### 6.1 十层行为包

原型里 60 人、每日 12 时辰、共 30 日，合计 21,600 次决定。各层生效的占比如下。

| 层 | 何时成立 | 例 | 实测占比 |
| --- | --- | --- | --- |
| 1 强制 | 卧病、禁闭、昏迷 | 在延寿堂卧病 | 1.5% |
| 2 处分 | 有未执行完的处罚 | 未时到大殿罚跪香 | 0.1% |
| 3 反应 | 感知到必须处理的事 | 去戒律院举报 | 不足 0.1% |
| 4 情节与指派 | 被事件选中，或被上级点名 | 监院派去帮厨 | 并入第 5 层 |
| 5 值守 | 此刻轮到的要紧岗位 | 厨务、巡夜、山门 | 4.6% |
| 6 生理紧急 | 饥或困跌破危险线 | 饿极、昏沉不支 | 基准月为 0 |
| 7 集体 | 日历上的集体活动 | 早课、过堂、布萨 | 48.1% |
| 8 岗位 | 本职的日常时段 | 藏主守阁、知客迎客 | 4.5% |
| 9 身份 | 所属人群的默认作息与差事 | 就寝、出坡、武僧习武 | 33.1% |
| 10 自由 | 以上都不成立 | 按需求挑设施 | 7.7% |
| 越轨 | 性格让人不执行本该生效的包 | 贪睡、怠工、夜里偷食 | 0.4% |

两条补充规则。

- 何时重算：每日排班时把当天十二格一次算好，即 v0.2 的班表物化。之后只有三种情况重算：当前的包结束，感知到事件，有人下了命令。
- 越轨不是一层包。它是性格加需求让人在某个时辰跳过第 7 到 9 层，这正是《上古卷轴 IV》里低责任心 NPC 偷东西的来路。

### 6.2 日程是数据

包的条件里可以写日历键。匹配次序照《星露谷物语》：先具体日子，再天气，再季节，最后默认。

```yaml
package: shaolin.busa            # 布萨诵戒
layer: 7
who:  {org: shaolin, status: monk}
when: {day_of_month: [1, 15], slot: 未}
do:   {place: place:shaolin:daxiongbaodian, act: chant}
```

集体活动不需要专门的“集合”机制，给所有人同一条日程即可。《哥特》里两个人每天到同一处闲谈，就是各自日程里写了同一个地点。领众的人靠岗位包区分：同一时辰，维那的包是“领诵并点名”，其余人是“随众”。

### 6.3 需求

| 需求 | 每时辰消耗 | 日常供给 | 危险线及后果 |
| --- | --- | --- | --- |
| 饥 | 7；睡时 3 | 两餐各 45 | 低于 12：守戒低者当场找吃的 |
| 困 | 6；作务与习武更多 | 睡一时辰 30 | 低于 25 起不来；低于 10 就地昏睡 |
| 洁 | 1；作务与习武更多 | 晨起 6、浣洗 25、沐浴 60 | 只影响心情 |
| 群 | 1.6，随“合群”增减 | 闲谈 16、共事 4、课诵与过堂各 2 | 只影响心情 |
| 志 | 3 | 做本方向的功课 20 上下；履职 6 | 只影响心情 |

前四项是《模拟人生》的通用需求删减而来。第五项按《矮人要塞》的做法因人而异：武僧要练武，学僧要读经，禅僧要坐禅。

两条校准规则，都是原型跑出来的。

- 每项需求按“一日收支”校准，日常供给必须盖得住日常消耗。
- 性格改的是门槛和权重，不是生理常数。把“馋”做成饿得快，这个人就长期挨饿、夜夜行窃；改成“起念的门槛低”才像人。

### 6.4 自由时段怎么选

1. 列出此刻能用的交互：设施开放，准入通过，还有空工位。
2. 给每个交互算分：各项需求的迫切度乘以该交互的增量，再加性格偏好。
3. 在最高的三项里按分数加权抽一项，抽签用计数器式随机数。
4. 占住工位。满了就顺次选下一项，都满了就去廊下散步。

迫切度的算法：

```latex
u(x) = \left(\frac{100 - x}{100}\right)^{2} + 0.05
```

第 3 步不取最高而在前三里抽，是《模拟人生》避免所有人做同一件事的办法。基准月里自由时段的选择是：闲谈 756 次、浣洗 294、小憩 219、沐浴 148、习武 118、读经 103、坐禅 26。因工位已满而改选 200 次，越界占用 0 次。

### 6.6 时间花在哪

清众每日睡 3.2 个时辰，课诵、坐禅、斋食合计 6.3 个时辰，作务不到 1 个时辰；执事的作务是 2.5 个时辰。早晚课到课率 99.3%，换五个种子在 98.7% 到 99.6% 之间。24 次缺课全部出自精进低于 35 的 4 个人。

## 7 第三步之三：活是怎么干完的

活由场所和岗位派给人。常设的走任命，临时的走工作板，人只负责认领和执行。

### 7.1 四种来活方式

| 来源 | 例 | 借自 |
| --- | --- | --- |
| 任命的岗位 | 典座每日寅、卯、巳、申四个时辰在厨房 | v0.2 人岗分离 |
| 轮值排班 | 山门每日两人，从清众里轮 | v0.2 班表 |
| 工作板 | 挑水 4 人、打柴 6 人、舂米 4 人、菜园 6 人、洒扫 9 人 | RimWorld 的工作优先级；v0.2 的差事表 |
| 场所派活 | 行脚僧到了客堂，由客堂安排挂单与随众 | 《潜行者》Smart Terrain |

工作板的认领规则：每人按优先级从上往下扫，认领第一件还有空额的；认领即预约，别人不能再领。基准月发布的 870 人次差事全部完成。

### 7.2 差事是一串固定步骤

每件差事定义成固定的小步骤，照 RimWorld 的 Toil：前往、取物、使用设施、交付。每一步发一条 v0.2 命令。

所以 NPC 干活和玩家操作经过同一套物理校验和规范校验，不留后门。库房锁着，NPC 没有钥匙也进不去。

### 7.3 为什么日常生活不上规划器

[F.E.A.R. 的 GOAP](https://pages.cs.wisc.edu/~dyer/cs540/handouts/gdc2006_orkin_jeff_fear.pdf) 解决的是战斗里的步骤组合问题。日常生活的步骤是固定的，《模拟人生》、RimWorld、《矮人要塞》都用固定步骤加条件检查。

缺前提时不靠个人规划，靠制度补。厨房缺米，v0.2 的规则会生成“调粮”需求，再变成差事挂到工作板上。链条由世界接起来，不由某个人在脑子里推出来。

留一个口子：江湖人物的长途办事，如寻人、送信、求医，先用“差事模板”拼接。模板不够用时再评估规划器，届时它只替换第 9 层里的一小块。

### 7.4 补位：一次厨房减员的两种结局

实验 N1：第 10 日起典座与三名饭头同时病倒 4 日，厨房只剩 1 人。两次运行只差一条规则：监院是否派清众代理。

| 30 日合计 | 无人代理 | 监院派人代理 |
| --- | --- | --- |
| 减量的餐数（共 60 餐） | 8 | 0 |
| 饥饿的人·时辰占比 | 8.4% | 0 |
| 偷食（起） | 58 | 7，与基准相同 |
| 举报（次） | 109 | 1 |
| 处分（起） | 45 | 1 |
| 互相不睦（对） | 17 | 1 |
| 心情低落的人·日占比 | 7.6% | 0.2% |

同一场病，差别只在“岗位空了有没有人补”。没人补时，需求、越轨、见证、举报、处分、结怨这条链自己跑完了全程：第 12 到 14 日三天里偷食累计从 8 起涨到 55 起。

这是机制的压力测试，不代表寺里真会这样判。它说明 v0.2 的“指派”一级必须先于 NPC 上线。

### 7.5 结伴而行

商队、行脚僧、帮众出行按队伍处理。队伍有一个带队人，带队人的包决定去向，其余人的包是“跟随”。

队伍在路上只按路程推进，到了场所再由场所派活。这是《潜行者》里小队在智能区域之间迁移的做法，原型没有覆盖这一条。

## 8 第三步之四：看见、记住、传开、追究

消息只从目击者出发，靠人与人见面往外传。规矩只对被看见、被举报的事起作用。全知的 NPC 不像人。

### 8.1 感知

事件发生时，v0.2 已经冻结了见证人名单。感知层只做一件事：把事件交给每个见证人的处理函数，照《哥特》的 perceptions。

| 事件类 | 谁能感知 | 处理 |
| --- | --- | --- |
| 眼前的越轨 | 同一场所、醒着的人 | 记入见闻；决定是否举报 |
| 响动：打斗、钟鼓、呼救 | 相邻场所的人 | 记入黑板；可能前去查看 |
| 缺席 | 负责点名的岗位 | 维那在早晚课点名，记缺课 |
| 空铺 | 巡夜查到的寮房 | 记“夜不在寮”，列入当夜嫌疑 |
| 少了东西 | 负责清点的岗位 | 典座晨起清点，发现失窃，立案 |
| 公告 | 在场全体 | 午斋后表堂，处分当众宣布 |

### 8.2 两种记忆

- 黑板：键值对，可带过期时间。存“我的床位”“我认领的工位”“刚才听到钟响”。Minecraft 的村民就是这样记住自己认领的床和工作站。
- 见闻：指向事件日志里某一条的指针，外加强度、经手层数、从谁那里听来。它不复制事件内容，所以不会和日志不一致。每人最多留 16 条，弱的先忘。

“昨夜你见过谁”这类盘问不需要另存数据。v0.2 的在场记录可以现算，再按被问者的记忆强度过滤。

### 8.3 传闻

结构取自 Minecraft 的 gossip：每条见闻有强度，定期衰减，转述时减弱。源头取自《矮人要塞》：只有目击者能起头。数值是我们自己定的。

| 参数 | 原型取值 |
| --- | --- |
| 目击时的强度 | 偷食 80、处分公告 60、失窃 50 |
| 每日衰减 | 2 |
| 每转一手的损失 | 12 |
| 不再外传的强度下限 | 25 |
| 一次闲谈转述几条 | 各说一条，挑对方不知道的里面最强的 |
| 对当事人本人说不说 | 不说 |

&#91;embedded content: 原型 npc\_spike.py 基准运行 · 第 6 至 30 日 · 种子 20261110\]

一件只有一人撞见、且没人举报的偷食，8 天后半数人听说，19 天后 59 人里有 40 人听说，最远传了四手。它没有传遍全寺，也没有被永远记住：到月末还记得的只剩 22 人。

传闻的速度由闲谈次数决定，闲谈次数又由“群”这项需求的收支决定。三次试跑主要只改了这一项的收支，最终听说的人数分别是 47、6、40。所以传闻参数要和需求一起校准，不能单独调。

### 8.4 真相与认知

传闻的内容不走样，会错的只有“那人是谁”。这条照《矮人要塞》：它的传闻从不失真，唯一的错来自隐藏身份。

放到天龙世界正好：易容者做的事，目击者记在他扮的那个人头上。见闻里存“看见的身份”，事件日志里存真身，两者由“以某身份出现”表连接。

谎言比易容多一步：它是一条没有目击事件支撑的断言。本方案只允许情节事件注入这类断言，普通 NPC 不会自己编造。原型没有覆盖易容与谎言。

### 8.5 从越轨到处分

1. 越轨。需求加性格让某人做了触犯规范的交互。物理上做得成，规范层打上标记。
2. 见证。同处的人和恰好巡到的人成为见证人。
3. 是否举报。纪律岗位必报。其余人的概率是 0.15 + 0.6 × 刚正 − 0.4 × 对当事人的好感，刚正折到 0 至 1，好感折到 −1 至 1。
4. 送达。见到任何一位纪律执事就当面禀告；见不到，就在巳时或申时去戒律院。
5. 无人指认时。典座清点发现失窃即立案；巡夜当夜记下的空铺者被传讯，认不认看本人的“刚正”。
6. 裁断。首座次日巳时裁断，首座不在由执事代。有人指认或本人认错才定罪，否则十日后成悬案。
7. 处分阶梯。罚跪香三日，杖责加禁闭二日，禁闭五日，迁单出寺。
8. 公告。午斋后表堂，在场者全部得知。
9. 余波。受罚者对举报人好感 −30，持续 60 日；守戒高的旁观者对受罚者 −5。

第 1 步取自《上古卷轴 IV》，第 5、6 步取自《矮人要塞》的证人指认与审问。

惯犯虚真（馋 92、守戒 22）在基准月里的记录：

| 日 | 事 | 结果 |
| --- | --- | --- |
| 2、4、8、11、17 | 丑时偷食，无人看见 | 典座次晨清点，五次立案，无人指认，成悬案 |
| 19 | 丑时偷食，被巡夜的僧值撞见 | 当场记下并上报 |
| 20 | 丑时又偷一次；巳时裁断第 19 日一案 | 午斋后表堂：罚跪香三日，59 人在场 |

延长到 90 日，同一个人偷了 16 次，被处分 4 次，四级阶梯各走了一遍，第 83 日迁单出寺。

## 9 第三步之五：好恶、心情、性格与一生

人与人的差别存在五项性格刻度里，人与人的亲疏存在一条条带期限的好恶修正里。两者都是数据，都能追到起因。

### 9.1 性格

五项刻度，0 到 100，开局定下，极少变动。做法取自《矮人要塞》的 facets：性格决定一个人怎么做，也决定他需要什么。

| 刻度 | 改什么 | 原型里的表现 |
| --- | --- | --- |
| 精进 | 贪睡与怠工的概率；功课类广告的加分 | 24 次缺课全出自精进低于 35 的 4 人 |
| 守戒 | 起念越轨的门槛 | 守戒 22 的虚真一个月偷食 7 次 |
| 刚正 | 举报的概率；被传讯时认不认 | 决定一起案子是结案还是悬着 |
| 合群 | “群”的消耗；闲谈广告的加分；转述的概率 | 决定谁是消息灵通的人 |
| 馋 | 偷食起念的门槛 | 馋 92 的人饱腹低于七成就起念，常人要低于三成半 |

原著人物另加词条。抽取到的性格词，如“鲁莽”“多疑”“重义”，按一张映射表折成刻度的增减。照《模拟人生 3》，每个词条只是一组权重修正，不写专门的代码。

### 9.2 好恶

好感等于底数加所有未过期修正项之和，范围 −100 到 100。结构取自《十字军之王 III》。

| 修正项 | 值 | 期限 | 叠加上限 | 起因 |
| --- | --- | --- | --- | --- |
| 底数：同寮、同方向、同岗 | +5、+4、+6 | 常驻 |  | 档案 |
| 底数：性格相近或相远 | 约 −10 至 +10 | 常驻 |  | 档案 |
| 谈得投机 | +4 | 30 日 | 8 条 | 闲谈事件 |
| 话不投机 | −4 | 20 日 | 5 条 | 闲谈事件 |
| 被他告发 | −30 | 60 日 | 1 条 | 举报事件 |
| 他犯过戒 | −5 | 30 日 | 2 条 | 处分公告 |
| 师徒、亲属、结义、仇怨 | 大数 | 常驻 |  | 原著关系 |

双方都不低于 25 记为好友，都不高于 −15 记为不睦。好恶反过来影响三件事：闲谈挑谁，看见了举不举报，听来的话信不信。

基准月末有 35 对好友，其中 34 对同寮、同方向或同岗；随机配对的话这个比例只有 52%。人以群分是自己长出来的，没有写规则。

### 9.3 心情

心情等于五项需求的加权平均加当前所有想法之和。想法是带期限的加减分：受训诫 −4（5 日）、受处分 −8（3 日）、受杖 −15（5 日）、沐浴 +4（1 日）、谈得来 +2（1 日）。做法取自 RimWorld。

三道线的初值直接取 RimWorld 的 35、20、5。

| 心情 | 后果 |
| --- | --- |
| 低于 35 | 怠工概率加 15 个百分点 |
| 低于 20 | 回避集体活动，独处 |
| 低于 5 且持续 | 触发人生事件：告假下山、还俗、出走 |

原型只实现了第一道线。

### 9.4 一生

每月、每年各有一次脉冲。脉冲时对每个人从事件池里按权重抽取，权重受性格、处境和好恶修正。做法取自《十字军之王 III》的 on\_action。

| 事件池 | 事件 | 主要权重来源 |
| --- | --- | --- |
| 寺院，每年 | 剃度、受戒、升座、闭关、游方、还俗、圆寂 | 年龄、精进、心情、岗位空缺 |
| 帮会，每年 | 入帮、升等、外派、叛出 | 功劳、好恶、帮内空缺 |
| 通用，每月 | 生病、痊愈、结怨、和解 | 需求的长期水平、好恶 |

v0.2 已有的老去、身故、继任、招收并入这里。人口总量另设调节器：寺里僧数低于目标，就提高剃度的权重。《模拟人生 3》让城镇自己有就业率之类的指标，再用它调后台人口，是同一个思路。原型没有覆盖这一节。

### 9.5 志向

原著人物各有一件放不下的事：复国、寻仇、求艺、寻亲、守戒。没有 LLM 时，志向只是一个常驻的行为包，层级在第 9 层，内容是一种差事模板：去某地，找某人，求某物。

它保证这些人不会在一个地方过一辈子。《矮人要塞》的人物也各有一个人生目标，达成时会记上一笔。

## 10 模拟精度与性能

精度分三档，只决定“算多细”，不决定“做什么”。同一个人被不被观察，时辰一级的行踪完全相同。

| 档 | 谁 | 算什么 | 省掉什么 | 对应的出处 |
| --- | --- | --- | --- | --- |
| 眼前 | 观察者所在场所里的人 | 时辰内细分到刻；逐条叙述；工位逐个预约 | 无 | 《刺客信条：起源》的 real；《潜行者》的 online |
| 个体 | 其余被单独模拟的人 | 每时辰一次决定；需求惰性求值；见证与传闻 | 时辰内的先后、叙述 | 《起源》的 virtual；《潜行者》的 offline |
| 批 | 背景人口 | 按人群整批结算 | 个人 | v0.2 抽象阶梯。《起源》居中的 bulk 是画面上的低模，文字世界用不上 |

“精度不参与决定”是一条可测的规则：观察者站在不同地方各跑一遍，全体人员的时辰级轨迹哈希必须相同。原型里观察者站在廊下，多生成了 860 条细节叙述，哈希不变。

这依赖计数器式随机数。用顺序随机数的话，多生成一条叙述就会改写全寺的未来。

### 10.1 成本

原型实测每次决定 5 到 6.5 微秒，纯 Python、内存结构，含见证、闲谈和案件。

| 规模 | 每日决定数 | 耗时 |
| --- | --- | --- |
| 原型 60 人 | 720 | 实测：30 日 0.14 秒 |
| 少林寺 300 人 | 3,600 | 按 6 微秒估：每模拟年约 8 秒 |
| 全图 3,000 个体 | 36,000 | 按 6 微秒估：每模拟年约 80 秒 |

后两行是估算，不是实测。落到 SQLite 会变慢；班表每日物化加需求惰性求值会把“个体”一档的决定数压下来。两头相抵后的真实数字要等 C8 测。

### 10.2 原型纠正的六处设计

这六处都是写文档时想不到、跑起来才暴露的。

1. 值守的人永远没空举报。厨房的人在戒律院开门的两个时辰都当值，五个人眼看着偷食，一起也报不上去。改成当面禀告任何一位纪律执事。
2. 需求收支不平。“洁”和“群”的供给盖不住消耗，全员贴地，自由时段只剩闲谈和浣洗。改成按一日收支校准。
3. “馋”做成了饿得快。这个人长期挨饿，成了一台偷食机器。改成起念的门槛低。
4. 嫌疑名单永远是空的。巡夜只看现场，看不见谁不在床上。加上查寮记空铺。
5. 浴室只有 6 个位。60 人一个月轮不到一次。容量改按人数乘频次反推。
6. 传闻速度被“群”的收支牵着走。两组参数必须一起校准。

## 11 与 LLM 共存，和控制台

LLM 上线不需要改内核，只是给少数几份档案换一个操纵者。控制台只做两件事：替玩家发命令，和让你查任何人此刻为什么在做这件事。

### 11.1 操纵者接口

每份档案有一个操纵者。操纵者只做一件事：在内核给出的合法候选里选一个。

| 操纵者 | 怎么选 |
| --- | --- |
| 程序 | 第 6 节的行为包栈 |
| 玩家 | 控制台输入 |
| LLM | 读一段情境，回一个候选编号和一句话 |

给 LLM 的输入是五样：档案摘要、五项需求、最强的 5 条见闻、眼前的人及好恶、此刻合法的候选动作。候选由程序先算好。

三条约束：

- LLM 只能选，不能造。它的输出仍是一条命令，仍过物理和规范两层校验。
- 第 1、2、5、7 层不交给 LLM。卧病、受罚、值守、集体活动没有可选的余地。
- 超时或输出不合法，立刻回落到程序的选择。世界不等它。

这样算下来，一个 LLM 角色每天真正需要调用模型的时辰不多：原型里第 3、6、10 层合计不到全部决定的 8%。本地小模型负担得起。

### 11.2 控制台

| 命令 | 作用 |
| --- | --- |
| 看、去、取、放、用、说 | 玩家的六个动词，各对应一条内核命令 |
| 等 n | 推进 n 个时辰 |
| 谁在 地点 | 此刻在场的人和各自在做什么 |
| 查 某人 | 档案、需求、心情、当前生效的层及成立原因 |
| 迹 某人 日 | 某日十二时辰的轨迹 |
| 闻 某人 | 他知道哪些事，从谁那里听来 |
| 情 某人 | 他对谁有好恶，逐条修正项及起因 |
| 案 | 在查、已处分、悬案 |
| 为何 事件号 | 沿因果链回溯，v0.2 已有 |
| 日报 | 当日大事，v0.2 已有 |
| 跟 某人 | 观察者跟随某人，所到之处升到“眼前”一档 |

控制台不存状态。它的每条输出都能由库里的数据重新生成。

### 12.2 “像真人”的九条指标

“像真人”拆成九条能量的指标。原型值来自 60 人 30 日的基准运行。

| 指标 | 怎么量 | 原型值 | 通过线 |
| --- | --- | --- | --- |
| 有作息 | 早晚课到课率 | 99.3% | 97% 到 99.8%，不许是 100% |
